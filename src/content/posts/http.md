# 《一个 HTTP 请求的一生》

## 一、敲下回车

地址栏里的 URL 被拆开：协议、域名、端口、路径、查询串。

浏览器先翻缓存。强缓存没过期，直接用，连网都不出。过期了，带上 `If-None-Match` 或 `If-Modified-Since`，去问服务器还认不认。

Service Worker 若拦在前头，命中缓存就地返回，这一生还没开始就结束了。

## 二、找 IP

域名不认识，得查 DNS。

浏览器缓存、系统缓存、hosts 文件，一路往下问。都没有，交给本地递归解析器，它替我去问根、问 .com、问权威服务器，拿回一条 A 或 AAAA 记录，按 TTL 逐层缓存。

这一步省不掉，但可以提前做：DNS 预取、HTTPDNS。

## 三、建连接

TCP 三次握手。SYN，SYN+ACK，ACK。可靠连接建立。

HTTPS 再加一轮 TLS：协商版本与加密套件，验证服务器证书，交换密钥。TLS 1.3 一次往返完成，恢复会话还能 0-RTT。

HTTP/3 走 QUIC，架在 UDP 上，把传输握手和加密握手合成一次，少一个来回。

连接是稀缺资源，所以有 keep-alive、连接池、preconnect。

## 四、发请求

```
GET /posts/1 HTTP/1.1
Host: example.com
Accept: text/html
Accept-Encoding: gzip, br
Cookie: session=...
```

请求行说明意图，请求头交代上下文，请求体承载数据。

报文交给协议栈：TCP 分段，IP 封包，以太网成帧，经路由器逐跳转发，直到服务器门口。

## 五、服务器处理

先到负载均衡：TLS 卸载、限流、按路径转发。

Nginx 接住。静态资源直接回，动态请求转给应用服务器。

应用里走一遍：路由匹配、中间件（鉴权、日志、CORS）、查缓存、查库、调下游、拼响应。

然后写回状态码、响应头（`Content-Type`、`Cache-Control`、`ETag`、`Set-Cookie`）、响应体。

这一环的优化最多：CDN 边缘响应、服务端缓存、数据库索引、连接池、异步化。

## 六、回来

响应沿原连接返回，中途可能被 CDN 或代理缓存一份。

浏览器读状态码：200 正常，304 用本地缓存，301/302 跳转，4xx/5xx 出错。

读响应头：更新 HTTP 缓存，写入 Cookie，记下 `Content-Encoding` 准备解压。

## 七、渲染

HTML 解析成 DOM，CSS 解析成 CSSOM，两者合成渲染树，布局，绘制，合成上屏。

页面里的图片、脚本、样式表，每一个子资源，都是一次新的「一生」，只是路径短些，多数能命中缓存和已有连接。

关键渲染路径上的资源，优先级高；其余的，懒加载。

## 八、收尾

HTTP/1.1 空闲超时后四次挥手，连接关闭。

HTTP/2 一条连接多路复用，长期保持。

HTTP/3 的连接还能随网络切换迁移，0-RTT 恢复。
